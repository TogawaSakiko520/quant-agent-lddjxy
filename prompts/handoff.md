# 接手与交接提示词

请先显式读取 AGENTS.md、相关子目录规则、PROJECT_STATE.md、SPEC.md、ARCHITECTURE.md、ASSUMPTIONS.md 和当前任务关联文档，再读取真实 Git 状态及源码。不要依赖聊天记忆，不覆盖他人未提交改动。

新增或更新交接及其他仓库文档前，读取 [文档表达原则](../docs/AGENTS.md#文档表达原则)，区分当前实现、实际运行结果和未验证事项，详细证据留在对应记录。

目标：<需求 ID 与期望行为>。先陈述现状证据、影响范围、已授权动作和真正的阻塞项，然后执行有边界的小改动。不得因为缺实盘凭证阻止离线工作，不得擅自调用券商或解除实盘阻塞。

源码说明遵循 [根 AGENTS.md 的分层解释规范](../AGENTS.md#按业务语义分层解释qc-014唯一主规范)；交接优先说明流程、调用约定和未解决边界，不以注释密度判断可维护性。

连续可读性完善先保存本轮起始工作区快照，区分上一轮未提交成果与本轮新增说明。交接列出关键对象的来源、事实/目标/预算口径、重要调用及状态去向，保留上一轮证据与治理规则。

交接时更新 PROJECT_STATE 的唯一当前摘要：已实现能力、实际验证范围、证据入口、未验证事项和最小下一步。完整命令、结果、失败和产物清单集中到对应验收记录，历史阶段归档并维护引用；CHANGELOG 只保留主要变更及验证摘要。禁止将计划接口写成可运行功能，也不能用“后台继续”代替交付。
