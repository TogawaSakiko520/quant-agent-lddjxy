# 扩展、参数与接入

## 新增因子

先登记稳定 ID/版本、经济假设、公式、单位、方向、窗口和最少观测数、价格口径、available_at 规则、空值/极值/标准化规则及失效条件。实现只依赖当时可知数据，新增手算、边界和未来扰动测试；同步 docs/factors、配置说明、Schema 及需求映射。基本面因子必须先拥有可验证历史公开/可用时间。

## 更换数据源

把网络和供应商类型限制在 adapters。保存来源、版本、原始材料/价格/成交量、公司行动和各类时间；对供应商历史时点记录作明确声明。以契约测试验证时区、单位、修订、迟到、缺失、重复、异常价格和稳定证券 ID。原始材料与批准快照追加保存，不覆盖旧数据。

## 调整配置

所有资金、持仓、行业、换手、成本、价格缓冲和状态阈值均是演示参数。配置字段的单位和精确默认值必须以已校验配置和说明为准，修改时同步配置约束、测试、中文说明和文档；不要以参数调整掩盖错误。

若 90% 旧仓全部换到另一组证券，gross turnover 是 180%，100% 总换手约束可能使新目标本轮无法完成；应保留约束并解释剩余现金或延后目标。卖出成交与可用购买力不是跨账户通用等价，真实适配以券商确认和账户制度为准。

## 接券商与正式引擎

首轮没有可下实盘单的适配器。先完成 ADR-0001 的引擎验收、数据授权、独立环境/凭证、账户白名单和预算批准，再做隔离契约、恢复与模拟/影子测试。成熟引擎负责订单状态，不允许另建绕过它的入口。

普通 CI 不得取得实盘密钥。持续多进程运行前完成事务存储、执行者唯一性、备份恢复、告警值守与发布审批的验收；每项实际证据保存于对应验收记录，PROJECT_STATE 只更新当前摘要与证据入口。
