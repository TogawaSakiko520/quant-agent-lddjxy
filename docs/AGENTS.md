# 文档维护补充规则

先读根 AGENTS.md。本目录只维护各自职责的说明，不复制可独立演进的业务实现。公式、时间、单位、接口、配置和故障行为变化必须同步相关页与需求映射；已实现、计划、未验证、未批准必须区分。PROJECT_STATE 记录实测，文档不得编造通过记录。

注释规范统一引用根 AGENTS.md「按业务语义分层解释」（QC-014）。跨模块流程和完整推导留在对应文档，源码保留局部理解必需的边界说明。历史验收及审计记录保留原貌，以新增记录说明规范变更，不将旧逐句注释验收改写为新规范验收。

## 文档表达原则

本节是仓库文档表达原则的唯一入口，适用于根 README、运行手册、设计说明及其他仓库文档。目标读者理解基本 Python 和常见编程结构，但不预设其熟悉量化研究、市场机制、订单、账户、账务和回测。源码注释继续遵循根规则，不在这里维护第二套注释标准。

1. **先说用途和当前行为。** 先说明程序处理什么、执行什么动作、产生什么结果，再介绍实现机制；首次运行不能要求读者先理解完整架构。
2. **用具体对象解释。** 优先说行情、评分、目标股数、订单和现金变化，避免只用抽象术语串联流程。语法简单也不意味着业务含义无需说明。
3. **术语按使用场景解释。** 专业词首次出现在一个独立阅读入口时，简要解释本项目中的含义，后续使用统一名称；完整定义放相关主题文档，入口处可保留必要摘要，不扩写成术语百科。
4. **区分能力与证据。** 已实现表示代码具备该行为；实际验证过要指出验证范围和记录；已知缺陷、待验证和计划分别说明。通过离线演示不代表真实数据、外部券商、策略收益或持续运行已验收，不把未完成能力写成安装后即可使用。
5. **集中维护，局部可理解。** 完整命令/产物清单、公式、设计取舍和验证证据各有归属。其他位置以短摘要和链接衔接，既不复制多份完整说明，也不让关键步骤只剩“详见文档”。操作现场可以重复必要前提，技术专题可以保留完整推导，不为统一篇幅而削平差异。
6. **遵守文档分工。** 使用下表选择内容位置。新增页面须有清楚的独立职责；优先复用现有入口，不另建职责重叠的规则文件或教学版实现。
7. **采用稳定的仓库语言。** README、手册和设计说明描述用途、行为和边界，不使用AI对话、任务承诺或交付证明口吻。状态、变更与审计记录可保存具体日期、命令、结果和限制，不将这些过程细节重复搬到长期入口。
8. **准确完整优先。** 精简不能删掉必要前提、单位、失败后果或技术边界；不按字数、注释密度或术语数量判断质量，不新增关键词或文字密度检查器。
9. **修改前核对事实。** 对照实际源码、CLI参数、配置、目录、忽略规则及状态记录更新文档。区分仓库内可访问文件和运行后才生成的产物；核对相对链接与标题锚点。平台本地验证不等于全面平台支持，历史结果不冒称本次运行，不通过润色扩大能力。

### 内容归属

| 文档 | 维护的完整内容 |
|---|---|
| 根 README | 项目定位、当前能力和关键限制、首次运行摘要、少量主要阅读入口。 |
| 快速开始 | 首次选择环境、安装、demo、看结果及简单验证；每条环境路线可顺序完成。 |
| 操作手册 | 完成具体任务所需的前提、步骤、成功判定与失败处理。 |
| 技术参考 | 完整参数/产物、配置、契约、公式和恢复机制；操作现场保留必要摘要与链接。 |
| 架构、代码导读及专题说明 | 模块职责、调用关系、设计边界、公式和推导。 |
| 需求规格 | 预期行为及验收要求，不用需求文字代替实现证据。 |
| PROJECT_STATE | 唯一当前状态摘要、已验证/受阻范围、必要入口和下一步；完整历史迁至审计。 |
| CHANGELOG | 按时间的主要变化与必要验证摘要；详细实验/失败只链接相应记录。 |
| 审计记录 | 特定基线的发现、证据和限制；不把旧结论直接当作当前实现。 |
| 文档导航 | 按阅读目的组织链接与简短说明，不复制正文或另设标准。 |

历史迁移须保留原日期、基线、结论与失败，修正相对链接，明确归档适用范围；不把旧“当前阶段”并列放在 PROJECT_STATE。README 和正常操作示例采用新检出可自行生成的路径，不依赖某台机器已有的私有运行目录。工具安装、PATH 和环境重建集中到维护手册。

### 编辑前后的判断

编辑前先围绕这次任务判断：读者要完成什么，需要哪些前提、步骤、成功标志和失败入口？这条事实由哪里主要维护，更新原文或迁移内容是否已经足够？内容说的是当前能力、预期设计、历史证据，还是当前任务边界？据此选择内容归属，不默认在文末不断追加新段落。

编辑后从实际入口顺着操作和链接走读：新读者能否独立完成任务、找到结果并判断下一步？删减是否迫使读者反复跳转，新增说明是否重复已有正文，术语是否在必要处解释，能力表述是否有实现或证据支撑？简洁与完整冲突时，优先保留任务所需信息，再把深入说明放到适当参考位置。

这些问题用于帮助判断，不是逐题填报、固定表格或评分标准；只需简要说明影响修改结果的选择和依据，不输出完整思考过程。维护提示词引用本节，只补充当前任务关注点。命令验证与业务问题分开记录，不在文档润色中顺便改变实现。
