# ADR-0001：首轮用 FakeBroker 验证契约，正式引擎待验收

状态：已采用离线演示路线；LEAN 适配未验收。日期：2026-09-13。

## 决策

首轮使用确定性 FakeBroker 和持久化测试驱动完成数据→决策→订单→成交→对账→报告。其成交假设及合成数据只能验证工程，不作为生产撮合、收益评估或真实成交表现的依据。核心不引入供应商类型，不要求券商凭证、Docker 或付费数据即可运行离线演示。

## 依据

LEAN 核心使用 Apache-2.0；LEAN CLI 的本地运行路线要求 Docker，官方入门文档另外列明付费组织资格。源代码运行是另一条路线，Linux 构建要求以所固定版本文档为准。核心开源不代表 CLI、行情、云服务与账户服务免费。依据：[官方入门](https://www.quantconnect.com/docs/v2/lean-cli/key-concepts/getting-started)、[本地回测](https://www.quantconnect.com/docs/v2/lean-cli/backtesting/deployment)、[核心代码及许可](https://github.com/QuantConnect/Lean)。这些前提由本轮架构核实记录提供，正式接入前必须再次核实所选版本。

## 后续引擎验收

固定引擎提交/镜像及 CLI 版本；验证本地运行和账号资格、数据授权、输入与日历映射、公司行动、费用/滑点、订单状态与重启恢复、断线与取消竞态、固定样本测试可控性。保留统一报告、原始引擎输出及可解释差异。缺数据、超时、引擎不可用必须显式失败，不得静默回退并宣称完成 LEAN 回测。

接入时复用引擎订单状态管理，由唯一适配入口写单。真实数据回测、持续模拟和实盘分别验收，不以通过 FakeBroker 测试代替。
